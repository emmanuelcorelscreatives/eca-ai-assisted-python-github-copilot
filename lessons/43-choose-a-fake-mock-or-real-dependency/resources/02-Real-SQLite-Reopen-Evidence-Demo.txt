import sqlite3


def test_file_backed_sqlite_survives_a_new_connection(tmp_path):
    database_path = tmp_path / "expenses.db"

    connection = sqlite3.connect(database_path)
    try:
        connection.execute(
            "CREATE TABLE expenses (id INTEGER PRIMARY KEY, amount TEXT NOT NULL)"
        )
        connection.execute(
            "INSERT INTO expenses (amount) VALUES (?)",
            ("12.50",),
        )
        connection.commit()
    finally:
        connection.close()

    connection = sqlite3.connect(database_path)
    try:
        row = connection.execute(
            "SELECT amount FROM expenses WHERE id = ?",
            (1,),
        ).fetchone()
    finally:
        connection.close()

    assert row == ("12.50",)

Run from the project root:

python -m pytest tests/test_real_sqlite_evidence.py -q

Interpretation:
- The test uses the real SQLite engine.
- The database is a real file under pytest's temporary path.
- The first connection is committed and closed before the second connection reads.
- This demonstrates the capability of file-backed SQLite.
- A production persistence test should apply this pattern through the application's production repository so it also exercises the application's schema and SQL.
